# 高铁线路图与查询系统

一个以高铁站点为背景的 C++ 图算法课程项目：把站点和连接关系组织成图，提供站点维护、连通性判断、环检测和最少中转路径查询，并把修改后的数据保存到文本文件。

**课程团队项目；项目负责人 / 维护者：迟凡杰。** 当前仓库展示团队代码，负责人身份不表示所有模块均由一人完成。仓库尚未保留可核验的逐模块分工表，因此不虚列个人贡献比例。

## 功能与实现

| 功能 | 入口 | 技术点 |
| --- | --- | --- |
| 站点新增、删除、修改与查询 | `BusAdd`、`BusErase`、`BusModify` | 站点 ID、内部编号与关系维护 |
| 路线新增/删除与保存 | `AddEdge`、`DeleEdge`、`PrinText` | 数组邻接表、双向边及文本持久化 |
| 城市可达性与连通范围 | `Find`、`Union`、`UnionSet` | 带路径压缩的并查集 |
| 环检测 | `FindCircle` | 节点度数和队列处理 |
| 最少中转路径 | `Dijkstra`、`FindMinPath` | 优先队列、距离松弛、前驱记录与路径回溯 |
| 图接口练习 | `Graph` / `ArrayGraph` | 抽象接口及具体实现 |

路径查询将每条连接的权重设为 `1`，比较经过的连接数量。它**不使用真实铁路时刻、里程、票价或换乘等待时间**，不能作为真实出行规划服务。

## 编译运行

环境：Windows、Visual Studio 的“使用 C++ 的桌面开发”组件。源文件沿用原工程 GBK 编码；打开 `.sln` 后如提示升级工具集，可重定向到已安装的 Windows SDK 和 MSVC。

也可在 **Developer PowerShell for Visual Studio** 中，从仓库根目录执行：

```powershell
Set-Location '高铁三级项目'
New-Item -ItemType Directory -Force build | Out-Null
cl /nologo /EHsc /std:c++14 /source-charset:.936 /execution-charset:.936 main.cpp Func.cpp RailClass.cpp /Fe:build/rail-route.exe
./build/rail-route.exe
```

务必将工作目录设为 `高铁三级项目/`：程序相对读取 `rail.txt`、`Edge.txt`。在 IDE 中启动时，将“调试 → 工作目录”设为 `$(ProjectDir)`。

## 数据格式与演示

`rail.txt` 每行是站点 ID 和不带空格的名称：

```text
1 Alpha
2 Beta
3 Gamma
```

`Edge.txt` 每行是一条无向连接的两个**内部编号**；编号按站点文件的行顺序从 1 开始：

```text
1 2
2 3
```

可把合成数据复制到临时工作副本中演示。启动程序，选择菜单 `9`，依次输入起点 `1`、终点 `3`，预期路线为 `Alpha → Beta → Gamma`：经过 2 条连接，途中经过 1 个中间站。菜单 `3` 可检查两点连通性。

“保存信息”和“退出系统”会写回当前目录的两份数据文件。自带的少量教学用城市与连接**不是经过核验的真实高铁线路数据**；演示前建议复制一份，避免覆盖原样例。

## 当前状态与限制

- 这是保留原课程实现的控制台项目，没有在线服务、地图 UI 或真实交通数据接口。
- 当前整理环境未安装 C++ 工具链，未重新构建运行；上述预期路线依据算法及给出的样例说明，不是新增测试报告。
- 删除站点/边后的编号与邻接表重建、重复边、起终点相同及非法输入仍有待验证的边界，不应声称任意数据下结果均正确。
- 数据结构使用固定容量数组，不提供并发访问或大规模图性能保证。
